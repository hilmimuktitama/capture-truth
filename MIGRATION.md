# Migration to 0.5.1

0.5.1 keeps the default library and `capture` behavior as a reviewable evidence pack. Export is now explicit: use `capture --output-mode export|both` with `--profile`, or `export --pack <pack> --profile <profile>`. Candidate review can write a reviewed pack with `--output-mode pack`, allowing sequential review before a final export. An omitted candidate-review output mode preserves the historical portable-summary export response; explicit `export` or `both` requires `--profile`, and `both` returns exactly `{ reviewed_pack, export }`. MCP offers `capture.export` with required `pack` and `profile`.

0.5.0 aligned the bundled contract schemas with Truth Tools. Copy or regenerate source, source-ref, and candidate-claim artifacts using the canonical 0.5.1 schemas; runtime validation now rejects recursive raw-like keys and malformed nested values.

Use `createEvidencePack` and `candidate_claims`. Candidate claims require the enumerable 0.5.1 derivation marker (`derivation_version` and `source_material`). Replace any source fetch step with an exported JSON input. Use `normalizeJiraIssue` or `normalizeConfluencePage` only on records already fetched by your own process. Select an explicit export profile; raw-local-only cannot be portable. Reviewer names/timestamps are declared attribution only; Capture Truth does not authenticate them.

Portable profiles retain claims derived from `structured_fields` and `metadata`. They always exclude `raw_body` and `mixed` claims, including after JSON/filesystem/MCP round trips. Legacy, forged, or source-inconsistent claims are diagnosed and excluded rather than guessed safe. Approval now validates every candidate, source reference, and unique source id in the full pack, so forged approvals fail immediately. MCP exposes the same candidate review helper as the CLI/API. URL sanitization covers source/ref paths, encoded and nested URLs, query parameters, and fragments.
